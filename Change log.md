# Change log – Buyer-List tool

| 2026-10-28 | **Auction simulation (separate tool).** New skill `.claude/skills/auction-simulation/` runs the sealed-bid auction simulator in `../Auction Theory` on a finished run (`run_auction.py run --project <slug>`): Monte Carlo over irrationality levels, where a higher fit means less mispricing. It only reads `06_list_data.json`, `state.json`, `08_final.lock` and the longlist Excel (checked against the lock), reads the deal team's Status column if asked (not Feedback, which holds the analyst's round notes), and writes nothing here; reports go to `Auction Theory/output/`. No rule, stage, gate, hook or agent of this tool changed. START HERE has a short section. | Max Zuffer, 2026-10-28: a Python auction simulator for the M&A process that integrates with the buyer lists (simultaneous sealed bids, Monte Carlo over irrationality, fit lowers irrationality). |
| 2026-10-28 | **Review rounds with analyst feedback.** New runs build the list in rounds of 10, 20, 20 and the final 50 new names per side (`init --rounds`; `--rounds off` = one round). Every round runs the full pipeline and ends with a validated Excel ("- round n of N"). The analyst gives feedback in chat; Claude records only the analyst's words (`feedback add`: keep / drop / maybe / data-wrong, `--new` for added names). `round next` refuses until every new name has feedback. In later rounds: dropped names never return; earlier names that weren't dropped stay; data-wrong names are re-profiled with the note (gates 3/4); added names are researched and keeps get a place; every sourcing and critic task carries the feedback, and each round needs new lenses written from it (gate 2). Every new row of a review round is audited. The Feedback column shows the earlier rounds' feedback, plus a new "Rounds & feedback" sheet. The Stop hook makes a finished review round ask for feedback ("Feedback needed:"). New module `buyerlist/rounds.py`. Adversarial review (3 reviewers + 3 verifiers, 27 confirmed findings), fixed: feedback and round snapshots are matched by website domain, and a name shown in a closed round keeps its id and side; with debate scoring the judge leaves PE-owned holdings out, and the program sets Portfolio 5 only for a qualifying platform; a platform whose qualifying sponsors were all dropped goes to Excluded with a warning; a carried sponsor already satisfies the platform must-include; holdings without an overlap class fail gate 6; `excel` rejects old list data; `feedback list/status` show the closed rounds and no longer crash mid-round; `init --rounds auto` scales the schedule down for small lists, and the schedule is checked before the run folder is touched; name matching between holdings and platforms is tighter. 66 tests. | Max Zuffer, 2026-10-28: first a draft of 10 strategic and 10 financial investors, then the analyst researches each and gives feedback, and the next run includes that feedback. Schedule 10 / 20 / 20 / 50; feedback in chat only; hard effects plus sourcing guidance; full process per round. |
| 2026-10-28 | **Stricter PE platforms and closer holdings.** A PE-owned strategic is shown as its sponsor's portfolio company only with strategic fit >= 3.0 and Product >= 4 (ranked, horizontal). If the sponsor's own fit on ticket, geography and criteria (portfolio left out) is below 3.0, the platform needs Rank 1 (fit >= 3.8) and Product 5. The check is per (platform, sponsor) pair. A non-qualifying platform gives no label, rank lift or Portfolio-5 credit; it appears on the PE reroutes and Excluded sheets with the reason. Investor holdings now carry a product-overlap class (same products / same category / adjacent), and only the first two count and are shown. New module `buyerlist/platforms.py`; `tasks make 3 --ids … --per-agent N`. | Max Zuffer, 2026-10-28: a PE firm that does not fit the investment criteria needs a Rank-1 platform in exactly the same industry; all portfolio companies need closer product overlap; a platform needs a minimum BD fit (decided: 3.0 with Product >= 4). |
| 2026-10-20 | **Run options and profile-based financial scoring.** New `buyerlist options` command, stored in the run state and logged: which sides are debated, retry on/off, and financial scoring by debate or by profile. New `buyerlist/fiscore.py` gives a deterministic financial score from the sourced profiles with the same weights. New `tasks cancel <step>` neutralises queued agent tasks without stopping the running ones. Sponsor matching ignores descriptors ("managed by …") so it doesn't create duplicates. Owner and fund-size normalisation added. | Max Zuffer, 2026-10-20: stop the queued subagents and build the list from the data analysed so far. Strategic: Controller + judge, no retry. Financial: profile score. Audit: yes. |
| 2026-10-19 | **Second review: 19 confirmed defects fixed.** Profiles are normalised when loaded: owner-type synonyms, fiscal-year strings such as "2024/25 (FYE 31 Mar 2025)", and stakes such as "45,5 %". The profiler task lists the exact owner types, and redo tasks carry each profile's validation errors. Undisclosed shareholders become a warning: the row is flagged "not verified PE-free" and always audited. Outdated figures are warned about and shown as outdated. A fund holder stays a sponsor whatever its ultimate owner. A subsidiary is folded into its parent only when the parent itself stays listed. `tasks make 2/5c` re-issue invalid outputs, not only missing ones; `--ids` opens the right stage. Audit resolutions are bound to the exact findings and claims they resolve. Duplicates on the lists are judged by website. The shell guard now parses quotes and heredocs properly and respects the working directory. The Stop hook decides from this turn's own tool calls and sees completion notices in any transcript entry shape. 54 tests. | Second review workflow (3 reviewers + 3 verifiers). Live run: before the fix, 54 of 69 profiles failed on vocabulary alone; after it, 1 of 99. |
| 2026-10-19 | **Adversarial review: 45 confirmed defects fixed.** Gates 2, 4, 5a, 5c, 5d, 5e, 6 and 8 recompute their outputs from the inputs and compare them with the files, so stale or hand-edited derived files now fail. Controller, round-2 and judge outputs are tied by manifests to the hash of what they reviewed. CLI-only files are always write-protected. The shell guard was rewritten: strict CLI fast path, read-only rule for run files, heredoc and non-canonical path handling. Passed outputs and the run state are read-only on disk, and the final lock follows the run state. The Stop hook reads only the final message; WAITING is accepted only while a workflow is running. Parsing tolerates markdown and never drops lines silently. The retry round counts missing dimensions, and retried companies keep their kept points. Universe dedupe is by domain; a same-name/different-domain pair is an error resolved via exclude.json / distinct.json; type is set by majority. Ownership is counted through ultimate owners, and "PE-backed" without a sponsor is an error. Route additions are rebuilt on every run. Ranked PE platforms always keep a sponsor on the financial list. Audit coverage is per claim with stable sampling. Revenue is shown with one decimal below 100. `init --force` wipes the run. `tasks make 3 --ids --note` re-profiles named companies. 45 tests. | Review workflow (5 reviewers + 5 verifiers); findings verified by reproduction. |
